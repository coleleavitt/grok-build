Generated test plan

  1. Select account by ranking when active_index is absent
    Verify credential resolution does not implicitly pin to index 0 when active_index is null/absent; selection should follow normal ordering rules (health/tier/name).
  2. Preserve sticky selection when explicit active_index is healthy
    Verify explicit active_index pins selection to that account when it is healthy/ready.
  3. Mark selected account rejected with retry-after and rotate
    On Anthropic rate limit with Retry-After header, selected account is marked rejected/cooled down and next resolve rotates to another ready account.
  4. Apply 5-minute cooldown fallback when retry-after missing
    If rate limit response has no Retry-After metadata, system applies default cooldown window (300 seconds) and marks account rejected.
  5. Invalidate process-local bearer cache on rate limit record
    After recording rate limit for selected account, cached bearer credential is cleared so next credential fetch cannot reuse exhausted token.
  6. Sampler Anthropic RateLimited error follows rotate+resubmit recovery
    Sampler RateLimited outcome should trigger credential mark/rotate/refresh workflow and then use existing resubmit path to continue successfully.
  7. Sampler returns exhausted only when no replacement account remains
    If all Anthropic accounts are rejected/unavailable after RateLimited handling, session should return exhausted outcome.
  8. No secret leakage in auth/log artifacts during offline test runs
    Validate security constraint that test/log endpoints and artifacts do not expose bearer tokens or refresh secrets; intended for CI safety checks without live API dependency.
